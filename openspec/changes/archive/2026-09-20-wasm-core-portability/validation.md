## Validation details and resolved failures

- Final Wasm CTest runs: Debug 0.67 seconds, Release 0.56 seconds (two entries each).
- Final native core runs: Debug 2.30 seconds, Release 0.68 seconds (one entry each).
- Native lifecycle regression: Debug 3.72 seconds, Release 0.44 seconds.
- `audit.py`: both native comparisons pass, 62 common sources, three Wasm backends,
  98 compile commands per Wasm configuration.
- `verify_configuration.py`: missing SDK and unsupported C++17 fail explicitly
  in isolated fixtures; SDK activation metadata is never changed.
- `test_minimal_runtime.py`: both minimal graphs, desktop graph and source/module
  rejection cases pass.
- Desktop regeneration initially selected system pip without cymbal. Repeating
  with installed Python 3.10 and Scripts directories on PATH succeeded. No extra
  package installation or unrelated desktop code change was required.
- Earlier core runs used system Node 24.13.0 through CMake's default emulator.
  The final entry explicitly selects activated SDK Node 24.19.0; both final runs
  use that runtime, as confirmed by generated CTest commands.
- Global-property validation exposed the SDK's 64 KiB stack default. The shared
  Wasm executable options now reserve 1 MiB, retaining the production allocator.
- Corrected wasm32 allocation header alignment, stale realloc headers, unaligned
  canary/signature access and cross-thread bookkeeping rather than weakening tests.
- The approved UTF policy is reflected in design/spec and tested in both configs;
  a valid Unicode round-trip test also exposed decoded-character iterators being
  passed as byte iterators, now corrected.

Build/test logs remain under ignored engine `build/` directories. Source/docs and
OpenSpec artifacts remain reviewable in the working tree. Existing warnings from
bundled EASTL and SDK/CMake shared-library detection do not fail these static builds.
